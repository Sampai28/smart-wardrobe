\begin{abstract}
This paper presents Smart Wardrobe, a locally deployed, privacy-preserving outfit recommendation system that combines visual compatibility scoring with event-aware classification. The system accepts user-uploaded clothing images through a Streamlit web interface, extracts 2048-dimensional embeddings using a pretrained ResNet50 backbone, and stores item representations in a SQLite database. Outfit recommendations are generated by enumerating all valid top-bottom-shoes combinations and scoring each with two complementary signals: a visual compatibility score derived from pairwise cosine similarity between item embeddings, and an event suitability score from a trained multilayer perceptron classifier. The event classifier is trained on the Fashion Product Images dataset, containing 44,101 clothing items with usage labels spanning Casual, Formal, Sports, Ethnic, Party, Smart Casual, and Travel categories. Training with inverse-frequency class weighting over 30 epochs on GPU achieves 71.8 percent validation accuracy. The final outfit score is a weighted combination of both signals, enabling recommendations tailored to six user-selected event types: casual, office, wedding, party, date night, and gym. The system is fully local with no external API dependencies, processes all wardrobe items at upload time, and ranks outfit combinations in real time.
\end{abstract}

\begin{IEEEkeywords}
outfit recommendation, ResNet50, visual embeddings, event classification, fashion compatibility, cosine similarity, Streamlit, SQLite, deep learning
\end{IEEEkeywords}

\section{Introduction}
% ─────────────────────────────────────────────────────────────

\subsection{Motivation}

Choosing an appropriate outfit for a specific occasion is a task that combines aesthetic judgement, contextual awareness, and personal taste. For many people, assembling a well-coordinated outfit that suits the occasion requires both familiarity with fashion principles and knowledge of what items are available in their wardrobe. Intelligent recommendation systems can assist with this task by automatically evaluating garment compatibility and occasion suitability.

Most existing fashion recommendation work focuses on one of two objectives: aesthetic compatibility (do these items look good together?) or personalised retrieval (what should this user buy next?). Neither directly addresses the problem of composing outfits from items a user already owns, filtered for a specific social occasion. This gap motivates the Smart Wardrobe project.

\subsection{Problem Statement}

Given a personal wardrobe of clothing items (uploaded as photos), and a target event type (e.g., office, wedding, gym), the system must identify the top-N outfit combinations -- each comprising one top, one bottom, and one pair of shoes -- that are both visually compatible and appropriate for the specified event.

This problem has two interacting sub-problems:
\begin{enumerate}
    \item \textbf{Visual compatibility}: Do the selected items coordinate aesthetically in terms of colour, texture, and style?
    \item \textbf{Event suitability}: Are the selected items appropriate for the target occasion?
\end{enumerate}

No existing fashion dataset provides outfit-level labels for both sub-problems simultaneously. The Smart Wardrobe system addresses this by using two separate scoring models and combining their outputs.

\subsection{Contributions}

The main contributions of this work are:

\begin{itemize}
    \item A fully local, end-to-end outfit recommendation pipeline requiring no external APIs or cloud services.
    \item A two-signal scoring framework that combines unsupervised visual compatibility (cosine similarity over ResNet50 embeddings) with supervised event suitability (MLP trained on Fashion Product Images usage labels).
    \item An event-to-usage mapping that bridges user-facing event types (casual, office, wedding, party, date night, gym) to dataset usage categories (Casual, Formal, Ethnic, Sports, etc.) with calibrated weights.
    \item A Streamlit web application providing a complete user interface for wardrobe management and outfit recommendation.
    \item A SQLite-backed wardrobe store that persists clothing embeddings and thumbnails across sessions, discarding original images for privacy.
\end{itemize}

\section{Related Work}
% ─────────────────────────────────────────────────────────────

He et al. \cite{b1} introduced ResNet, which resolved the vanishing gradient problem in deep CNNs via residual skip connections, enabling 152-layer networks. ResNet50's global average pooling output produces a 2048-dimensional feature vector widely adopted as a universal visual embedding for downstream fashion tasks. The Smart Wardrobe system uses this pretrained backbone directly without fine-tuning.

Han et al. \cite{b2} proposed learning outfit compatibility using bidirectional LSTMs over sequentially ordered item embeddings, and introduced the Polyvore dataset of 21,889 human-curated outfits. While this approach requires outfit-level labelled training data, it established pairwise visual similarity as a baseline compatibility signal. Vasileva et al. \cite{b3} extended this by learning type-conditioned embedding subspaces -- one projection matrix per item-type pair -- demonstrating that compatibility is a type-relative rather than globally defined relation.

Tangseng et al. \cite{b4} is the most directly related prior work, recommending outfits from a personal closet by training a neural outfit grader on 409,776 Polyvore outfits. Like our system, it enumerates combinations from a personal wardrobe and scores them, but relies on supervised outfit-level labels whereas Smart Wardrobe uses unsupervised cosine similarity augmented by event classification.

He and McAuley \cite{b5} extended Bayesian Personalised Ranking with visual product features (VBPR), enabling cold-start recommendations for unseen items. This provides a framework for incorporating user preference signals that could extend the Smart Wardrobe system in future work.

A key gap across all related work is the absence of event or occasion labels. No Polyvore-based system conditions recommendations on the social context of the outfit. The Fashion Product Images dataset \cite{b6} addresses this with item-level usage annotations, which the Smart Wardrobe system uses as its event classification training signal.

\section{Dataset}
% ─────────────────────────────────────────────────────────────

\subsection{Fashion Product Images Dataset}

The event classifier is trained on the Fashion Product Images dataset \cite{b6}, sourced from Myntra, an Indian fashion e-commerce platform. The dataset contains 44,424 product listings with high-resolution product images and the following metadata per item: \texttt{id}, \texttt{gender}, \texttt{masterCategory}, \texttt{subCategory}, \texttt{articleType}, \texttt{baseColour}, \texttt{season}, \texttt{year}, \texttt{usage}, and \texttt{productDisplayName}.

The \texttt{usage} column is the primary supervision signal for the event classifier, containing eight categories. After removing the Home class (1 sample), 44,101 items remain across seven classes: Casual (34,406; 77.5\%), Sports (4,025; 9.1\%), Ethnic (3,208; 7.2\%), Formal (2,345; 5.3\%), Smart Casual (67; 0.15\%), Party (29; 0.07\%), and Travel (26; 0.06\%).

The dataset spans three master categories: Apparel (48.2\%), Accessories (25.4\%), and Footwear (20.8\%), covering 143 fine-grained article types including T-shirts, Shirts, Casual Shoes, Jeans, Kurtas, Heels, and Handbags. Gender distribution includes Men (50\%), Women (42\%), and Unisex/Boys/Girls (8\%), and items span years 2007--2019 across four seasons.

\textbf{Class imbalance:} The Casual class dominates at 77.5\% of samples. This is addressed during training via inverse-frequency class weighting and weighted random sampling, which up-samples minority classes during each training epoch.

\subsection{Personal Wardrobe Dataset}

The inference wardrobe comprises 600 clothing images curated from the Fashion Product Images library: 200 tops, 200 bottoms, and 200 shoes. Items are selected to span the full range of usage categories and article types, ensuring the wardrobe covers all six supported event types.

\section{System Architecture}
% ─────────────────────────────────────────────────────────────

\subsection{Overview}

The Smart Wardrobe system is composed of five modules: visual embedding extraction, persistent wardrobe storage, visual compatibility scoring, event suitability classification, and the Streamlit recommendation interface. Fig.~\ref{fig:pipeline} shows the full pipeline.

At upload time, each clothing item is processed once through the embedding extractor and stored. At recommendation time, all outfit combinations are scored in a single batched operation and the top-N results are returned to the user.

\begin{figure}[htbp]
\centerline{\includegraphics[width=0.48\textwidth]{fig_pipeline.png}}
\caption{Smart Wardrobe pipeline. Embedding extraction happens once per item at upload. Compatibility and event scoring happen at recommendation time over all combinations.}
\label{fig:pipeline}
\end{figure}

\subsection{Visual Embedding Extraction}

Clothing images are processed through a pretrained ResNet50 \cite{b1} with the final classification layer removed, producing a 2048-dimensional embedding vector per image. The model is loaded via \texttt{torchvision.models.resnet50(weights=ResNet50\_Weights.DEFAULT)} and run in evaluation mode with gradient computation disabled.

Input preprocessing follows the standard ImageNet pipeline:
\begin{enumerate}
    \item Resize to $224 \times 224$ pixels
    \item Convert to float tensor in $[0, 1]$
    \item Normalise by ImageNet mean $\mu = [0.485, 0.456, 0.406]$ and standard deviation $\sigma = [0.229, 0.224, 0.225]$
\end{enumerate}

The output of the global average pooling layer (shape $2048$) serves as the item embedding. This transfer learning approach leverages rich low-level features (colour, texture, edges) and high-level features (object shape, style patterns) learned during ImageNet pretraining. Embeddings are computed on GPU if available, with automatic CPU fallback.

\subsection{Wardrobe Storage}

Embeddings are persisted in a SQLite database with the following schema:

\begin{verbatim}
CREATE TABLE items (
  id        INTEGER PRIMARY KEY,
  name      TEXT NOT NULL,
  category  TEXT NOT NULL,
  embedding BLOB NOT NULL,
  thumbnail BLOB,
  added_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
\end{verbatim}

The \texttt{category} column is constrained to \texttt{'top'}, \texttt{'bottom'}, or \texttt{'shoes'}. Embeddings are serialised as 32-bit float byte arrays using \texttt{numpy.ndarray.tobytes()}, avoiding JSON overhead for 2048-dimensional vectors. A $100 \times 100$ pixel JPEG thumbnail is stored directly in the database as a \texttt{BLOB}, ensuring UI display does not depend on the original image file being present. After embedding extraction, the original image is not retained, preserving user privacy. A category index (\texttt{idx\_items\_category}) accelerates per-category retrieval.

\subsection{Visual Compatibility Scoring}

Compatibility between a three-item outfit (top $t$, bottom $b$, shoes $s$) is computed from pairwise cosine similarities between their embeddings:

\begin{equation}
\text{avg\_sim} = \frac{1}{3}\bigl[\cos(t,b) + \cos(t,s) + \cos(b,s)\bigr]
\label{eq:avg_sim}
\end{equation}

\begin{equation}
\text{compat} = \frac{\text{avg\_sim} + 1}{2} \;\in\; [0,1]
\label{eq:compat}
\end{equation}

Equation~\eqref{eq:compat} normalises the cosine similarity range $[-1,1]$ to $[0,1]$ for consistent combination with the event score. For batch scoring of all $T \times B \times S$ combinations, vectorised row-wise cosine similarity is applied to stacked embedding matrices, avoiding Python-level loops:

\begin{equation}
\cos_{\text{row}}(A, B)_i = \frac{A_i \cdot B_i}{\|A_i\| \cdot \|B_i\| + \epsilon}
\label{eq:rowcos}
\end{equation}

where $\epsilon = 10^{-8}$ prevents division by zero. For a wardrobe of 200 items per category ($200 \times 200 \times 200 = 8{,}000{,}000$ combinations), all scores are computed in a single GPU pass in under one second.

\subsection{Event Suitability Classification}

\subsubsection{Model Architecture}

The event classifier is a four-layer MLP that maps a ResNet50 embedding to a probability distribution over seven usage classes:

\begin{equation}
f_\theta: \mathbb{R}^{2048} \rightarrow \mathbb{R}^{7}
\label{eq:mlp}
\end{equation}

The architecture is:

\begin{center}
\small
Linear(2048, 512) $\rightarrow$ BatchNorm $\rightarrow$ ReLU $\rightarrow$ Dropout(0.3) \\
$\rightarrow$ Linear(512, 128) $\rightarrow$ BatchNorm $\rightarrow$ ReLU $\rightarrow$ Dropout(0.2) \\
$\rightarrow$ Linear(128, 7) $\rightarrow$ Softmax
\end{center}

Batch normalisation after each linear layer stabilises training and reduces sensitivity to learning rate selection. Dropout regularisation at rates 0.3 and 0.2 mitigates overfitting on the small minority classes.

\subsubsection{Training}

ResNet50 embeddings for all 44,101 training items are pre-computed and cached to disk as a NumPy \texttt{.npz} archive (\texttt{data/embeddings\_cache.npz}), so subsequent training runs load from cache without re-running ResNet50. Pre-computation processes all 44k images in approximately 25 minutes on GPU.

The dataset is split 80/20 (stratified by class) into 35,280 training and 8,821 validation samples. To address class imbalance, \texttt{WeightedRandomSampler} up-samples minority classes so each batch contains a more balanced class distribution, combined with inverse-frequency class weights in the cross-entropy loss:

\begin{equation}
w_c = \frac{1}{N_c + \epsilon}
\label{eq:classweight}
\end{equation}

where $N_c$ is the number of samples in class $c$. The Adam optimiser \cite{b7} is used with initial learning rate $10^{-3}$, reduced by factor 0.5 on validation loss plateau (patience 2). Training runs for a maximum of 30 epochs with early stopping (patience 5) if validation accuracy does not improve. The best checkpoint is saved to \texttt{models/event\_classifier.pth}.

\subsubsection{Event-to-Usage Mapping}

The six user-facing event types are mapped to weighted combinations of dataset usage classes:

\begin{table}[htbp]
\caption{Event-to-Usage Mapping Weights}
\begin{center}
\renewcommand{\arraystretch}{1.15}
\begin{tabular}{|l|l|}
\hline
\textbf{Event} & \textbf{Usage classes (weight)} \\
\hline
Casual     & Casual (1.0), Smart Casual (0.7), Travel (0.5) \\
Office     & Formal (1.0), Smart Casual (0.8) \\
Wedding    & Ethnic (1.0), Formal (0.8), Party (0.6) \\
Party      & Party (1.0), Smart Casual (0.7), Casual (0.3) \\
Date Night & Smart Casual (1.0), Party (0.8), Casual (0.4) \\
Gym        & Sports (1.0) \\
\hline
\end{tabular}
\label{tab:mapping}
\end{center}
\end{table}

For a given item with predicted usage probabilities $\{p_c\}$, the event suitability score for event $e$ is:

\begin{equation}
\text{event\_score}(e) = \frac{\displaystyle\sum_{c \in \mathcal{U}(e)} w_{e,c} \cdot p_c}{\displaystyle\sum_{c \in \mathcal{U}(e)} w_{e,c}}
\label{eq:eventscore}
\end{equation}

where $\mathcal{U}(e)$ is the set of relevant usage classes for event $e$ and $w_{e,c}$ is the corresponding weight from Table~\ref{tab:mapping}. The outfit-level event score is the mean of the three item-level scores.

\subsection{Final Scoring and Ranking}

The final score for each outfit combination is:

\begin{equation}
\text{score} = \alpha \cdot \text{compat} + (1 - \alpha) \cdot \text{event\_score}
\label{eq:final}
\end{equation}

with $\alpha = 0.5$ as the default weight, configurable by the user. All combinations are ranked by this score and the top-N outfits are returned.

\section{Streamlit Web Application}
% ─────────────────────────────────────────────────────────────

The user interface is implemented as a multi-page Streamlit application (\texttt{app/app.py}) with four pages accessible from a persistent sidebar:

\textbf{Upload Page:} Users upload a clothing image (JPG/PNG, up to 200 MB), enter an item name, and select a category (top, bottom, or shoes). On submission, the ResNet50 extractor processes the image, the embedding and thumbnail are stored in SQLite, and the sidebar wardrobe count updates. The extractor is cached with \texttt{@st.cache\_resource} so ResNet50 loads only once per session.

\textbf{My Wardrobe Page:} Displays all stored items in three columns (Tops, Bottoms, Shoes). Each item is shown as a thumbnail card with its name, add date, and a delete button. Empty-state messages guide users who have not yet uploaded items.

\textbf{Recommend Page:} The user selects an event type from a dropdown and the desired number of outfits (1--10). On clicking ``Get Recommendations'', all wardrobe combinations are scored and the top-N results are displayed as ranked cards. Each card shows the three item thumbnails side by side with individual compatibility, event suitability, and combined score bars colour-coded green (above 75\%), yellow (55--75\%), or red (below 55\%). If the event classifier has not been trained, a fallback mode using compatibility-only scoring is activated with an informational notice.

\textbf{About Page:} Documents the system pipeline, tech stack, and supported event types.

The Streamlit application is launched with:
\begin{verbatim}
streamlit run app/app.py
\end{verbatim}

Overall validation accuracy reached \textbf{71.8\%} with weighted F1 of 0.75. The model achieves near-perfect recall (0.95--0.98) for Ethnic, Formal, and Sports classes -- critical for the office, wedding, and gym event types -- at the cost of lower precision, reflecting the effect of class-weighted training that prioritises minority class recall. Casual achieves high precision (0.99) due to its dominant representation in the training data.

Smart Casual (F1 0.08) and Party (F1 0.27) perform poorly due to insufficient training samples (67 and 29 respectively). These classes would benefit from data augmentation or synthetic sample generation. Travel (26 samples) achieves reasonable recall (0.80) despite its small support, suggesting the Casual-adjacent visual characteristics of travel clothing are learnable from limited examples.

\subsection{Training Dynamics}

The model converged steadily from 20.2\% accuracy at epoch 1 to 71.8\% at epoch 30. Validation accuracy milestones: 25.2\% (epoch 3), 47.4\% (epoch 5), 57.5\% (epoch 13), 66.2\% (epoch 16), 70.3\% (epoch 27). No early stopping was triggered within 30 epochs, indicating the model continued to improve throughout training. The training loss stabilised below 0.001 by epoch 10, with accuracy gains driven by better calibration on minority classes.

\subsection{System Performance}

Embedding extraction: approximately 0.15 seconds per image on GPU (ResNet50 forward pass). Batch scoring of 125 outfit combinations: under 0.05 seconds. For the full 200-item wardrobe ($200 \times 200 \times 200 = 8{,}000{,}000$ combinations), vectorised scoring completes in approximately 3--5 seconds on GPU. SQLite read latency for 200 items per category is under 10 milliseconds.

\section{Discussion}
% ─────────────────────────────────────────────────────────────

\subsection{Design Choices}

\textbf{Unsupervised compatibility:} Using cosine similarity over pretrained ResNet50 embeddings -- rather than a supervised compatibility model -- allows the system to function without any labelled outfit training data. This makes the approach applicable to any personal wardrobe immediately, without requiring outfit-level annotation.

\textbf{Item-level event classification:} Training an event classifier on item-level usage labels rather than outfit-level occasion labels is a pragmatic choice driven by data availability. While outfit-level occasion labels would provide a stronger training signal, no such dataset exists publicly. The item-level approach still produces meaningful outfit-level event scores by averaging per-item predictions.

\textbf{Embedding storage over image storage:} Discarding original images after embedding extraction both preserves privacy and reduces storage requirements. A 2048-dimensional float32 embedding requires 8 KB versus a typical clothing image at 200--500 KB. The 100$\times$100 JPEG thumbnail (approximately 5 KB) is retained solely for UI display.

\textbf{SQLite over server-side database:} SQLite requires no server process, configuration, or network access, aligning with the project's fully local, zero-dependency deployment model.

\subsection{Limitations}

\textbf{Class imbalance:} The Fashion Product Images dataset is heavily skewed toward Casual items (77.5\%), limiting event classifier performance for minority classes (Party, Smart Casual). This is a data limitation rather than a modelling limitation.

\textbf{No personalisation:} The current system produces the same recommendations for any user with the same wardrobe and event selection. Personalisation based on user feedback or historical preferences is not implemented.

\textbf{Category constraint:} Recommendations are limited to three-item outfits (top + bottom + shoes). Accessories, outerwear, and other garment types are not supported in the current version.

\textbf{Compatibility baseline:} Cosine similarity over raw ResNet50 embeddings is an unsupervised baseline. A model trained on labelled compatible/incompatible outfit pairs (e.g., type-aware embeddings \cite{b3}) would likely produce higher compatibility accuracy.

\section{Conclusion}
% ─────────────────────────────────────────────────────────────

This paper presented Smart Wardrobe, a locally deployed outfit recommendation system that combines visual compatibility scoring with event-aware classification. The system addresses the gap in existing fashion AI work by explicitly modelling occasion suitability -- a dimension absent from all major outfit compatibility benchmarks. Key outcomes include:

\begin{itemize}
    \item A working end-to-end Streamlit application supporting upload, wardrobe management, and event-tailored outfit recommendation.
    \item An event classifier achieving 71.8\% validation accuracy and weighted F1 of 0.75 on the Fashion Product Images dataset.
    \item A fully batched scoring pipeline capable of evaluating millions of outfit combinations per second on GPU.
    \item A privacy-preserving design that discards original images after embedding extraction.
\end{itemize}

Future work includes: (1) training a supervised compatibility model on labelled outfit pairs to replace the cosine similarity baseline, (2) incorporating user feedback for personalised recommendations, (3) data augmentation for minority event classes, (4) replacing ResNet50 with a CLIP or ViT backbone for richer semantic embeddings, and (5) extending the wardrobe model to support accessories and outerwear.
