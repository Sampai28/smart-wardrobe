\begin{abstract}
This paper presents Smart Wardrobe, a locally deployed, privacy-preserving outfit recommendation system that combines visual compatibility scoring with event-aware and gender-aware classification. The system accepts user-uploaded clothing images through a Streamlit web interface, extracts 2560-dimensional embeddings by combining a pretrained ResNet50 backbone (2048-dim) with a CLIP ViT-B/32 encoder (512-dim), and stores item representations alongside gender metadata in a SQLite database. Outfit recommendations are generated by enumerating all valid top-bottom-shoes combinations and scoring each with two complementary signals: a visual compatibility score derived from pairwise cosine similarity between item embeddings, and an event suitability score from a trained multilayer perceptron classifier. The event classifier takes a 2563-dimensional input (2560-dim combined embedding concatenated with a 3-dim gender one-hot vector) and is trained on the wardrobe\_v2 dataset, a balanced subset of 5,994 clothing items across four usage classes: Casual, Ethnic, Formal, and Sports. Using a 70/15/15 stratified train/val/test split with inverse-frequency class weighting, the classifier achieves 88\% test accuracy and a macro AUC-ROC of 0.9631. Outfit recommendations are ranked by event confidence score and filtered by gender, enabling tailored suggestions for six user-selected event types. The system is fully local with no external API dependencies.
\end{abstract}

\section{Introduction}
% ─────────────────────────────────────────────────────────────

\subsection{Motivation}

Choosing an appropriate outfit for a specific occasion is a task that combines aesthetic judgement, contextual awareness, and personal taste. For many people, assembling a well-coordinated outfit that suits the occasion requires both familiarity with fashion principles and knowledge of what items are available in their wardrobe. Intelligent recommendation systems can assist with this task by automatically evaluating garment compatibility and occasion suitability.

Most existing fashion recommendation work focuses on one of two objectives: aesthetic compatibility (do these items look good together?) or personalised retrieval (what should this user buy next?). Neither directly addresses the problem of composing outfits from items a user already owns, filtered for a specific social occasion and gender context. This gap motivates the Smart Wardrobe project.

\subsection{Problem Statement}

Given a personal wardrobe of clothing items (uploaded as photos with gender tags), and a target event type (e.g., office, wedding, gym), the system must identify the top-N outfit combinations -- each comprising one top, one bottom, and one pair of shoes -- that are both visually compatible and appropriate for the specified event.

This problem has two interacting sub-problems:
\begin{enumerate}
    \item \textbf{Visual compatibility}: Do the selected items coordinate aesthetically in terms of colour, texture, and style?
    \item \textbf{Event suitability}: Are the selected items appropriate for the target occasion?
\end{enumerate}

An additional constraint is \textbf{gender coherence}: outfit combinations should not mix items tagged for different genders unless items are marked Unisex. No existing fashion dataset provides outfit-level labels for all three dimensions simultaneously. The Smart Wardrobe system addresses this by using two complementary scoring models with a gender-aware filtering gate.

\subsection{Contributions}

The main contributions of this work are:

\begin{itemize}
    \item A fully local, end-to-end outfit recommendation pipeline requiring no external APIs or cloud services.
    \item A hybrid 2560-dimensional embedding combining ResNet50 texture/shape features with CLIP semantic features, improving event classification accuracy over either backbone alone.
    \item A gender-aware recommendation system that filters outfit combinations to ensure gender coherence (Men, Women, or Unisex items only).
    \item An automatic embedding migration gate that re-embeds stored wardrobe items if the embedding dimension changes, enabling seamless model upgrades without user re-uploads.
    \item A two-signal scoring framework combining unsupervised visual compatibility (cosine similarity) with supervised event suitability (MLP on usage labels).
    \item A Streamlit web application providing a complete user interface for wardrobe management and outfit recommendation.
    \item A SQLite-backed wardrobe store that persists clothing embeddings, gender tags, and thumbnails across sessions, discarding original images for privacy.
\end{itemize}

\section{Related Work}
% ─────────────────────────────────────────────────────────────

He et al. \cite{b1} introduced ResNet, which resolved the vanishing gradient problem in deep CNNs via residual skip connections, enabling 152-layer networks. ResNet50's global average pooling output produces a 2048-dimensional feature vector widely adopted as a universal visual embedding for downstream fashion tasks. The Smart Wardrobe system uses this pretrained backbone as one of two complementary embedding sources.

Radford et al. \cite{b8} introduced CLIP (Contrastive Language-Image Pretraining), a dual-encoder model trained on 400 million image-text pairs via contrastive learning. CLIP's image encoder produces semantically rich embeddings that generalise to unseen visual categories. Unlike ResNet50, CLIP embeddings encode high-level semantic concepts (e.g., ``formal attire'', ``sportswear'') rather than purely visual low-level features, making them a natural complement for fashion event classification.

Han et al. \cite{b2} proposed learning outfit compatibility using bidirectional LSTMs over sequentially ordered item embeddings, and introduced the Polyvore dataset of 21,889 human-curated outfits. While this approach requires outfit-level labelled training data, it established pairwise visual similarity as a baseline compatibility signal. Vasileva et al. \cite{b3} extended this by learning type-conditioned embedding subspaces, demonstrating that compatibility is a type-relative rather than globally defined relation.

Tangseng et al. \cite{b4} is the most directly related prior work, recommending outfits from a personal closet by training a neural outfit grader on 409,776 Polyvore outfits. Like our system, it enumerates combinations from a personal wardrobe and scores them, but relies on supervised outfit-level labels whereas Smart Wardrobe uses unsupervised cosine similarity augmented by event classification.

He and McAuley \cite{b5} extended Bayesian Personalised Ranking with visual product features (VBPR), enabling cold-start recommendations for unseen items, providing a framework for incorporating user preference signals that could extend Smart Wardrobe in future work.

A key gap across all related work is the absence of event or occasion labels and gender-aware filtering. The wardrobe\_v2 dataset addresses this with item-level usage and gender annotations, which the Smart Wardrobe system uses as its primary training signal.

\section{Dataset}
% ─────────────────────────────────────────────────────────────

\subsection{wardrobe\_v2 Dataset}

The event classifier is trained on the wardrobe\_v2 dataset, a curated subset of the Fashion Product Images dataset \cite{b6} from Myntra, an Indian fashion e-commerce platform. The dataset contains 6,000 balanced product listings (2,000 tops, 2,000 bottoms, 2,000 shoes) with high-resolution product images and the following metadata per item: \texttt{id}, \texttt{file\_name}, \texttt{category}, \texttt{gender}, \texttt{subCategory}, \texttt{articleType}, \texttt{baseColour}, and \texttt{usage}.

\textbf{Usage classes:} The original Fashion Product Images dataset contains eight usage categories. In wardrobe\_v2, four low-sample classes are merged: Smart Casual and Party are absorbed into Formal and Casual respectively, while Home and Travel are merged into Casual. After merging, 5,994 valid items remain across four classes: Casual (4,095; 68.3\%), Sports (974; 16.2\%), Formal (498; 8.3\%), and Ethnic (427; 7.1\%).

\textbf{Gender distribution:} Men (3,616; 60.3\%), Women (2,253; 37.6\%), Unisex (125; 2.1\%).

\textbf{Class imbalance:} The Casual class dominates at 68.3\% of samples. This is addressed during training via inverse-frequency class weighting and \texttt{WeightedRandomSampler}, which up-samples minority classes during each training epoch.

\subsection{Data Split}

The dataset is partitioned using a stratified 70/15/15 train/val/test split: 4,195 training, 899 validation, and 900 test samples. Stratification ensures class proportions are preserved across all three splits.

\section{System Architecture}
% ─────────────────────────────────────────────────────────────

\subsection{Overview}

The Smart Wardrobe system is composed of six modules: hybrid visual embedding extraction, persistent wardrobe storage, embedding migration gate, visual compatibility scoring, event suitability classification, and the Streamlit recommendation interface.

At upload time, each clothing item is processed once through both extractors and stored with its gender tag. At recommendation time, a gender filter is applied before combination enumeration, and all remaining outfit combinations are scored in a single batched operation.

\subsection{Hybrid Visual Embedding Extraction}

Each clothing image is processed through two complementary backbones to produce a 2560-dimensional combined embedding:

\textbf{ResNet50 (2048-dim):} The pretrained ResNet50 \cite{b1} with the final classification layer removed is run in evaluation mode. Input images are resized to $224\times224$, converted to float tensors, and normalised by ImageNet statistics ($\mu=[0.485, 0.456, 0.406]$, $\sigma=[0.229, 0.224, 0.225]$). The global average pooling output produces a 2048-dim texture-and-shape embedding.

\textbf{CLIP ViT-B/32 (512-dim):} The CLIP image encoder \cite{b8} is loaded via \texttt{clip.load("ViT-B/32")} and run in evaluation mode. CLIP's own preprocessing pipeline (resize to $224\times224$, centre crop, normalise) is applied. The image encoding is L2-normalised before concatenation, producing a 512-dim semantic embedding.

The two embeddings are concatenated to form the final 2560-dim item representation:

\begin{equation}
\mathbf{e} = [\mathbf{e}_\text{ResNet} \;\|\; \mathbf{e}_\text{CLIP}] \;\in\; \mathbb{R}^{2560}
\label{eq:hybrid}
\end{equation}

This fusion combines ResNet50's colour/texture sensitivity with CLIP's semantic awareness of style categories, yielding a richer feature space than either backbone alone.

\subsection{Wardrobe Storage and Embedding Migration}

Embeddings are persisted in a SQLite database with the following schema:

\begin{verbatim}
CREATE TABLE items (
  id        INTEGER PRIMARY KEY,
  name      TEXT NOT NULL,
  category  TEXT NOT NULL,
  gender    TEXT NOT NULL DEFAULT 'Unisex',
  embedding BLOB NOT NULL,
  thumbnail BLOB,
  added_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
\end{verbatim}

The \texttt{gender} column stores Men, Women, or Unisex. Embeddings are serialised as 32-bit float byte arrays. A $100\times100$ JPEG thumbnail is stored as a BLOB for UI display. Original images are discarded after embedding extraction, preserving user privacy.

\textbf{Embedding migration gate:} On every application startup, the system checks all stored item embeddings against the required dimension (\texttt{EMBEDDING\_DIM = 2560}). Any items with mismatched dimensions are automatically re-embedded using the stored thumbnail via the current extractor, and their embedding blobs are updated in-place. This ensures seamless model upgrades without requiring users to re-upload their wardrobe.

\subsection{Visual Compatibility Scoring}

Compatibility between a three-item outfit (top $t$, bottom $b$, shoes $s$) is computed from pairwise cosine similarities:

\begin{equation}
\text{avg\_sim} = \frac{1}{3}\bigl[\cos(t,b) + \cos(t,s) + \cos(b,s)\bigr]
\label{eq:avg_sim}
\end{equation}

\begin{equation}
\text{compat} = \frac{\text{avg\_sim} + 1}{2} \;\in\; [0,1]
\label{eq:compat}
\end{equation}

Equation~\eqref{eq:compat} normalises cosine similarity from $[-1,1]$ to $[0,1]$. For batch scoring, vectorised row-wise cosine similarity is applied to stacked embedding matrices:

\begin{equation}
\cos_{\text{row}}(A, B)_i = \frac{A_i \cdot B_i}{\|A_i\| \cdot \|B_i\| + \epsilon}
\label{eq:rowcos}
\end{equation}

where $\epsilon = 10^{-8}$ prevents division by zero.

\subsection{Event Suitability Classification}

\subsubsection{Gender Feature Encoding}

Gender is encoded as a 3-dimensional one-hot vector over \{Men, Women, Unisex\}. This is concatenated with the 2560-dim embedding to form the 2563-dim classifier input:

\begin{equation}
\mathbf{x} = [\mathbf{e} \;\|\; \text{onehot}(g)] \;\in\; \mathbb{R}^{2563}
\label{eq:input}
\end{equation}

\subsubsection{Model Architecture}

The event classifier is an MLP that maps the combined feature vector to a probability distribution over four usage classes:

\begin{equation}
f_\theta: \mathbb{R}^{2563} \rightarrow \mathbb{R}^{4}
\label{eq:mlp}
\end{equation}

The architecture is:

\begin{center}
\small
Linear(2563, 512) $\rightarrow$ BatchNorm $\rightarrow$ ReLU $\rightarrow$ Dropout(0.3) \\
$\rightarrow$ Linear(512, 128) $\rightarrow$ BatchNorm $\rightarrow$ ReLU $\rightarrow$ Dropout(0.2) \\
$\rightarrow$ Linear(128, 4) $\rightarrow$ Softmax
\end{center}

\subsubsection{Training}

Combined embeddings for all 5,994 items are pre-computed and cached to \texttt{data/embeddings\_cache\_resnet\_clip.npz}. Gender one-hot vectors are concatenated at training time. The Adam optimiser \cite{b7} is used with initial learning rate $10^{-3}$ and weight decay $10^{-4}$, reduced by factor 0.5 on validation loss plateau (patience 3). Training runs for a maximum of 40 epochs with early stopping (patience 7).

Inverse-frequency class weights applied to the cross-entropy loss:
\begin{equation}
w_c = \frac{1}{N_c + \epsilon}
\label{eq:classweight}
\end{equation}

\subsubsection{Event-to-Usage Mapping}

The six user-facing event types are mapped to weighted combinations of the four usage classes:

\begin{table}[htbp]
\caption{Event-to-Usage Mapping Weights}
\begin{center}
\renewcommand{\arraystretch}{1.15}
\begin{tabular}{|l|l|}
\hline
\textbf{Event} & \textbf{Usage classes (weight)} \\
\hline
Casual     & Casual (1.0), Sports (0.3) \\
Office     & Formal (1.0), Casual (0.2) \\
Wedding    & Ethnic (1.0), Formal (0.7) \\
Party      & Casual (1.0), Ethnic (0.5) \\
Date Night & Formal (0.8), Casual (0.6) \\
Gym        & Sports (1.0) \\
\hline
\end{tabular}
\label{tab:mapping}
\end{center}
\end{table}

The outfit-level event score is the mean of three item-level scores:

\begin{equation}
\text{event\_score}(e) = \frac{\displaystyle\sum_{c \in \mathcal{U}(e)} w_{e,c} \cdot p_c}{\displaystyle\sum_{c \in \mathcal{U}(e)} w_{e,c}}
\label{eq:eventscore}
\end{equation}

\subsection{Gender Filtering and Final Ranking}

Before combination enumeration, items are filtered by the selected gender: only items tagged as the selected gender or Unisex are included. Outfits are then ranked strictly by event confidence score (descending), with cosine compatibility as a stable tiebreaker:

\begin{equation}
\text{rank} = \text{argsort\_desc}(\text{event\_score})
\label{eq:rank}
\end{equation}

\section{Streamlit Web Application}
% ─────────────────────────────────────────────────────────────

The user interface is implemented as a three-page Streamlit application (\texttt{app/app.py}):

\textbf{Upload Page:} Users upload a single clothing image (JPG/PNG), enter an item name, select a category (top, bottom, or shoes), and select a gender tag (Men, Women, or Unisex). On submission, the hybrid extractor processes the image, and the combined embedding, gender, and thumbnail are stored in SQLite. Both the ResNet50 and CLIP models are cached with \texttt{@st.cache\_resource} and loaded only once per session.

\textbf{My Wardrobe Page:} Displays all stored items in three sections (Tops, Bottoms, Shoes). Each item is shown as a thumbnail card with its name, gender tag, and a delete button.

\textbf{Recommend Page:} The user selects an event type, a gender filter (All, Men, or Women), and the desired number of outfits (1--10). On clicking ``Get Recommendations'', items are gender-filtered, all valid combinations are scored, and the top-N results are displayed as ranked cards. Each card shows the three item thumbnails with a \textbf{Confidence} score (event suitability) and a \textbf{Compatibility} score (cosine similarity), colour-coded green ($\geq$75\%), yellow (55--75\%), or red ($<$55\%).

\subsection{Training Dynamics}

The model converged steadily, reaching 80\% validation accuracy by epoch 5 and peaking at 89.3\% at epoch 30. Early stopping was triggered at epoch 37. Validation loss stabilised below 0.45, with training loss reaching 0.01 by epoch 20, indicating well-controlled overfitting through dropout and weight decay.

\subsection{System Performance}

Single-image embedding extraction: approximately 0.2 seconds on GPU (both ResNet50 and CLIP forward passes). Batch scoring of 1,000 outfit combinations: under 0.1 seconds. SQLite read latency for 200 items per category is under 10 milliseconds. The embedding migration gate completes re-embedding of 6 items in under 3 seconds on GPU.

\section{Discussion}
% ─────────────────────────────────────────────────────────────

\subsection{Design Choices}

\textbf{Hybrid ResNet50 + CLIP embedding:} ResNet50 captures low-level visual features (colour, texture, edges) while CLIP captures high-level semantic concepts (style, occasion). Concatenating both preserves complementary information that improves classifier generalisation, as confirmed by the ablation in Table~\ref{tab:ablation}.

\textbf{Class merging over class dropping:} Merging Smart Casual into Formal and Party into Casual (rather than dropping them) retains their training signal while avoiding the stratified split failure that occurs with 2-sample classes. The four resulting classes have sufficient support for reliable training.

\textbf{Gender as a feature and a filter:} Gender is used in two ways -- as a one-hot feature concatenated to the embedding (influencing event classification) and as a hard filter before outfit combination enumeration (ensuring gender-coherent recommendations). The filter is the more critical component: it prevents recommending men's tops with women's bottoms regardless of event score.

\textbf{Embedding migration gate:} Storing thumbnails in the database enables automatic re-embedding when the backbone changes. This design decision, while adding a small startup overhead, eliminates the need for users to re-upload items after model updates.

\textbf{Unsupervised compatibility:} Cosine similarity over the hybrid embedding allows the system to function without labelled outfit training data, making it applicable to any personal wardrobe immediately.

\subsection{Limitations}

\textbf{No outfit-level compatibility labels:} Cosine similarity is an unsupervised proxy. A model trained on labelled compatible/incompatible outfit pairs \cite{b3} would likely produce higher compatibility accuracy.

\textbf{No personalisation:} The system produces the same recommendations for any user with the same wardrobe and event selection.

\textbf{Category constraint:} Recommendations are limited to three-item outfits (top + bottom + shoes). Accessories and outerwear are not supported.

\textbf{Casual dominance:} Even after class merging, Casual remains 68\% of the dataset, causing Sports to have relatively lower precision (0.75).

\section{Conclusion}
% ─────────────────────────────────────────────────────────────

This paper presented Smart Wardrobe, a locally deployed outfit recommendation system combining a hybrid ResNet50+CLIP visual embedding with a gender-aware MLP event classifier. Key outcomes include:

\begin{itemize}
    \item A working end-to-end Streamlit application supporting upload with gender tagging, wardrobe management, gender-filtered browsing, and event-tailored outfit recommendation.
    \item A hybrid 2560-dim embedding (ResNet50 + CLIP) achieving 88\% test accuracy and AUC-ROC 0.9631 on the four-class wardrobe\_v2 dataset, outperforming either backbone alone.
    \item An automatic embedding migration gate enabling seamless backbone upgrades without user re-uploads.
    \item A privacy-preserving design that discards original images after embedding extraction, retaining only embeddings and thumbnails.
\end{itemize}

Future work includes: (1) training a supervised compatibility model on labelled outfit pairs to replace the cosine similarity baseline, (2) incorporating user feedback for personalised recommendations, (3) fine-tuning the CLIP encoder on fashion-specific data, and (4) extending the wardrobe model to support accessories and outerwear.
